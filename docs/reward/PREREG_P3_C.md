# 预登记：第三阶段实验 C，密集奖励加未见过的问答共同训练（探索，2026-11-07）

依据：

- 用户 11-07 的决定 3："先只搬训练侧（B 要用），冒烟测梯度占比，占比不到 5% 不跑 C，到了只交 rw_mx_g 一个臂作探索"。

本文件在 C 的第一个 GPU 任务（冒烟）交出之前提交，之后不改判据；开跑后的改动只记在第 6 节"执行说明"。

## 0. 一句话

RL 的每两次优化步里，有一步加一批没训过的问答（权重 0.1），看理解项在梯度里占不占得到一份；占得到，就只跑一个 V4 加掺入的臂作探索，看问答能不能高过不掺的 rw_g，同时成功率不掉。

用语：
- **掺理解数据（und_mix）：** 开关在 `vagen/und_mix.py`，11-07 从 reward-mix 搬到 reward-design（1ffd3967，只搬训练侧）。每 2 个优化步插一批 128 条问答，只在回答 token 上算下一词损失，乘 0.1 加进策略的梯度。
- **理解项梯度占比：** 插入的那一步，截断之前算 ‖理解项梯度‖ ÷（‖策略梯度‖ + ‖理解项梯度‖），日志键 `grad_mag_share_und`。
- **V4：** 主线的分组进度分加 keep 筛组，同 rw_g。

## 1. 掺什么（池子）

- 池子 `reward_runs/und_mix/pool_c0_20261107`（manifest 里记了 sha256），共 88,690 行：
  - P1 训练集 78,786 行，转成矩阵 SFT 的行格式（`reward/build_und_src.py`）；
  - P0 训练集 9,904 行，即矩阵 D 组的 P0_train 去掉 240 条视频。视频在 reward-design 上会走错的视频位置编码。
- C0 的 SFT 只训了轨迹（qa_*.jsonl 是空的），所以这些问答对 C0 都是新的。但画面不全是新的：P1 的行都出自 C0 自己的 SFT 任务，九成以上的图和 C0 训过的帧相同。所以是"没训过的问答，画面大多是 C0 训过的"。
- 和三个评测集都不重叠：P1 探针 838 道、X0 510 道、G0 300 道，按题号、任务、场景、图核对，排除 0 行。
- 走 LLaMA-Factory 路径抽查了 1,000 行，0 行出错。每行平均 147.8 个 token，其中答案 3.1 个。
- 配方用 C0 自己的 train.yaml：模板 qwen3_vl_nothink，cutoff 16384，不设像素上限。

## 2. 冒烟和门槛（用户的决定 3）

- **冒烟：** 8 卡 10 次，计划照 rw_g（C0 e8 起，3,000 道，V4），加 `und_mix: {pool, batch_size 128}`（interval 2、weight 0.1 是开关的默认值）。不评测（同 rw_mix_smoke：评测集为空，去掉挑选和评测停止规则），计划由 `reward/make_plans_p3.py c --which smoke` 生成。
  - 理解批插在第 0、2、4、6、8 个优化步，共 5 次，每次更新 1 个优化步。
- **门槛：** 5 次插入的 `grad_mag_share_und` 取中位数。
  - < 5%：不跑 C，报告停在这里；
  - 5%–50%：交 rw_mx_g 一个臂；
  - > 50%：先停下报用户，再定（任务书只写了下限，这一条是计划报告决定 3 的默认值）。
- **冒烟还核对：**
  - 第一批的样本只在回答 token 上算损失（`first_batch_rank<r>.json` 解码）；
  - 每次插入用时；
  - 读不出率、熵、KL 和 rw_g 前 10 次比，没有异常。
- 计划报告里说的"梯度占比按 P0 / P1 分开记"不做：现在的开关只给整批的占比，要分开就得每批多做一次反传。只报整批的。
