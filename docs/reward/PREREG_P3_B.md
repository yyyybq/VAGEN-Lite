## 0. 一句话

每次更新采完样后，用距离表判策略走到的每个回合：走对了，标签是它自己的回答；走错了，换成表给的动作。把这些"当时的提示 + 标签"当监督样本，下一词损失乘 λ 加进策略的梯度。看两条：成功率比不加标签的对照高 5 个点以上，同时每回合出错率低 3 个点以上。

## 1. 标签怎么来（代码 `vagen/dagger.py`）

- **只判训练回合，验证和评测不判：** 训练器只给训练批打上 `dagger_step`。
- **判一回合：**
  - 环境走这一回合之前，读位姿和步数。
  - 走完以后，从那个位姿重放环境执行了的动作，用表自己的运动模型和环境的碰撞检测。执行了的动作 = 它解析出、允许的动作，按顺序，个数等于步数走了几步。
  - 一个动作把表距离从 d 变成 d − 1，就是最优动作；被挡的移动永远不是。
  - 位姿所在的格不在表里，或在表里但到不了成功，就取 26 个相邻格里的最小距离，同本线的进度分（`distance_table_near`）。
- **对的回合，四条都满足：**
  1. 至少执行了一个动作，每个执行了的动作都是最优；
  2. 没有走到 done。本线的环境不开显式结束，这一条只是保险；
  3. 回答正好是标签的写法：`<action>a|b|</action>`，后面至多一个回合结束符，前后没有别的字，动作名小写、每个后面跟 `|`；
  4. 回答写的动作和环境执行的一个不差。环境在半回合到达目标后停下、步数用完、超过 5 个、不允许的动作，都会让写的比执行的多，这样的回合换标签，免得损失教了环境没执行的动作。

  环境读不出的回合一个动作也没执行，算错，换标签。
- **不用的回合，计数，不进样本：**
  - 表里没有这道题；
  - 起点或途中查不到距离；
  - 重放的终点和环境的终点不同（`pose_mismatch`）；
  - 步数对不上；
  - 已在目标；
  - 向导给不出标签；
  - 找不到损失 token；
  - 出错。
- **标签：**
  - 对的回合用自己的回答。
  - 错的回合用向导的：照 reward-jsrl 的 `jsrl_guide` 抄的贪心计划，从这一回合的起始位姿出发，每一步取让表距离最小、且严格变小的动作，同距离按合同里的动作顺序，最多走到剩下的步数。
  - 计划按 SFT 数据的切法切成回合：同一动作一段，一段最多 5 个。取第一段，写成策略答题的样子 `<action>a|a|</action><|im_end|>`。
  - 格是按 1 cm / 1 度合并的，所以一步偶尔会让距离降 2；向导取最小的，照收。
- **取哪些回合：**
  - 全部 24 道候选题的 8 局，在筛组之前取：全失败的组正是策略拿不到信号的地方。
  - 每次更新最多 96 条，是 8 张卡的整数倍（每卡 12 条），按种子和更新次数随机挑。
  - 范围是全部回合：对的、换过的都取。
- **监督样本：** 从这一局的行里直接切，不重渲染。
  - 回合前的 token，即同样的图和历史；接上标签的 token。
  - 行里的四行位置编码在前缀上照抄，标签每个 token 各行加 1。
  - 只带前缀里那几张图的像素。
  - 训练器对每个自己答的样本做精确核对：接续的位置编码和行里的相同、token 和 agent loop 记的回答相同、前缀里的图像 token 和像素数对得上。不过的样本计数，不用。
- **损失：**
  - 只算标签里的动作名和分隔符到 `</action>`，不含 `<action>` 和回合结束符。
  - λ × 全部损失 token 的平均下一词损失，加进这次更新唯一一个优化步的梯度。线上的设置是筛组目标 12 组 × 8 = 96 行 = 一个小批，所以每次更新只有一步。
  - 两项的梯度在截断前分别量：范数、占比、夹角，同掺理解数据的 `mix_gradients`。
  - λ 默认 0.5。
  - 策略项按行缩放（1/12），筛组没凑满时它的梯度会变小，监督项不变。所以两项的比例每次更新都量。
- **出错就停：**
  - 开关开着时，一次更新拿不到判过的回合，就停下这个运行，不悄悄当普通 RL 跑。原因可能是：agent loop 没送记录、表读不到、所有回合都不用。
  - 挑中的回合一个样本也做不出来，也停。

开关全部默认关：
- `actor_rollout_ref.actor.dagger` 由 rl-config `--dagger` 写，链的计划键是 rl `"dagger"`；
- agent loop、训练器、verl actor 各加了几行挂钩。
- rl-config 拒绝开关和这些一起用：
  - 掺理解数据；
  - 不拼接的历史模式；
  - 非 async 的 rollout；
  - rollout_correction 的 bypass 模式；
  - REMAX；
  - Ulysses；
  - fp16。

开关关着时，rl-config 写出的配置逐字节不变，有测试。

## 2. 记录

- **训练日志每次更新记：**
  - 回合数、判了的、对的 / 换的占比；
  - 最优动作命中率：执行了的动作里最优的占比；
  - 执行的都最优、但写的比执行的多或写法不对的回合数（`dagger/own_unexecuted`）；
  - 各种不用的回合数；
  - 样本数（自己答的 / 换过的）、精确核对不过被丢的样本数；
  - 两项的梯度范数和占比、监督项损失；
  - 每次更新秒数，含取样本用的秒数。
- `RUN/dagger/turns.jsonl`：每次取中的回合，记任务、位姿、判法和标签，供离线核对。
- `RUN/dagger/check.jsonl`：每次更新一行的前缀概率核对，带更新次数。续训的运行重复记的那次只算最后一行。
- `RUN/dagger/first_batch_rank<r>_step<k>.json`：第一批样本的标签和损失 token 解码。
- `RUN/dagger/steps.jsonl`：每次更新的梯度量数。

## 3. 核对运行（冒烟之前；用户 11-07："冒烟前先报"）

- **两个运行**，都是 8 卡 3 次，不评测：rw_dgc_s0（S0 + 标签）、rw_dgc_g（V4 + 标签）。
  - 设 `audit_only`：监督项照样算、照样反传量梯度，量完就丢，这次更新只用策略自己的梯度。所以这 3 次和不加标签完全一样。
- **用户要的核对：** 自己答的回合，前缀样本算出的每个 token 的对数概率，和这一行训练时记的 `old_log_probs` 比。`old_log_probs` 是训练器在更新前、用同一份权重、每卡一行重算的。分三组报：
  - **整行组：** 前缀 + 回答正好是整行，和重算的输入一模一样，应当约等于 0。这一组看的是比较本身对不对。
  - **前缀组：** 其余的。前缀切错了会在这里显出来。
  - **底线组：** 每个样本再和另一个样本放进同一个两行的批里算一遍。token 不变，只换了批的形状，差多少就是 bf16 舍入本身能差多少。每卡每个样本多一次不反传的前向。
- **读法（事先定）：**
  - 两个运行、各 3 次更新合起来算；也分运行报。
  - 四条都满足就算"相等"：
    1. 精确核对 0 处不同；
    2. 整行组平均 |差| ≤ 0.001；
    3. 前缀组平均 |差| ≤ 底线组平均 |差| 的 2 倍 + 0.001；
    4. 前缀组 |差| > 0.1 的 token 不超过 1%。
  - 某一组一个 token 也没有，就"判不了"。
  - 不管过不过，结果都先报用户，再交冒烟。
- **同时报：**
  - λ 0.5 时监督项在梯度里会占多少：训练日志 `actor/dagger_grad_mag_share_und` = ‖监督项‖ ÷（‖监督项‖ + ‖策略项‖），截断前，按运行取 3 次的中位数；
  - 换标签的占比、各种不用的回合数；
  - 标签对表的离线独立核对：`reward/dagger_check.py`，用造表时的合法性判法 FastGeometry 重放，不用环境的碰撞检测；
  - 损失 token 的解码。

## 7. 和任务书、计划报告不一样的地方

- 计划报告写"冒烟时用'自己答的回合，前缀算出的概率等于训练时记的'来核"。用户要在冒烟前报，所以多了一步核对运行（第 3 节），约 6 卡时。它不改训练，还多量了一个底线组，让读法有个量出来的参照。
- 核对运行和冒烟各两个运行（S0、V4 各一个），因为门槛按臂判。任务书写的是一个 8 卡 10 次的冒烟。
- 任务书"同题配对的每回合出错率"：判据用合并 705 局的出错率。两边是同一批题，所以是配对的。另报按题配对重抽的区间。
- "对的回合"多了两条：写法要和标签一样，写的动作要和执行的一样。这两条只会把回合推到"换标签"那边，不会让错的动作当成自己的标签。
- 标签最多到剩下的步数：任务书和计划报告没写，免得标签里有环境不会执行的动作。
