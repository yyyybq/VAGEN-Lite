## 2. 方向 1 的实现：和任务书逐条对照

| 任务书的要求 | 实现（开关都默认关；主线代码只加了默认关的开关） |
| --- | --- |
| 每个回合的优势 = 3.333 ×（0.99 × 下一回合的 φ − 这一回合的 φ），φ 查距离表 | `vagen/turn_credit.py` 的 `turn_values`：φ 是环境的 `current_potential_score`，环境用 `progress_version: optimal` 时就是查表的 φ = 1 − d ÷ (d\* + 4)；成功那一回合下一回合的 φ 记 1。奖励本身（成功 +5、碰撞、读不出）不进这一项（`turn_reward` 默认关） |
| 整条轨迹的组内比较只用 S0 的回报；8 条相同时记 0，题不丢 | 整局项是 S0 回报的 GRPO 优势（组内减均值、除以组内标准差 n−1，和 verl 的 grpo 一致，测试里逐数核过）；回报全相同的组得 0，留在批里 |
| 混合筛选关掉，不用 keep，24 道候选全部进梯度 | 筛选用 `nominal`，target_groups 24：每次抽的 24 道题全部进更新（S0 现在每次只留约 5–7 道有成有败的题，见 rw_s0 的 PROGRESS） |
| 两项各自整批标准化后相加，逐回合项权重 0.5 | 整局项除以它在整批 192 局上的标准差（均值本来就是 0）；逐回合项减整批回合的均值、除以整批回合的标准差（`baseline: batch_mean`）；每个回答 token 的优势 = 整局项 + 0.5 × 逐回合项；观察 token 是 0 |
| 前 50 次报告两项的分布和"逐回合项改变总优势正负号的回合占比"，一项占比低于两成就调权重 | 每次更新写进 RL 日志（`turn_credit/…`）：两项各自的第 10 / 90 百分位、逐回合项占总幅度的比例（`turn_magnitude_share`）、逐回合项把总优势翻号的回合占比（`sign_flip_share`，只算整局项不为 0 的回合）、整局项为 0 的回合占比、回报全相同的组数、进梯度的题数和回合数、查表未命中占比、停滞回合占比 |
| 查表未命中开相邻格兜底：取 ±1 cm / ±1° 格子里最小的 d | 新文件 `data_gen/interiorgs_v10/distance_table_near.py`：表里没有这个位姿，就取它周围 26 个格子（x、y 各 ±1 cm，朝向 ±1°）里可达成功的最小 d；26 个格子都没有才算未命中。环境开关 `optimal_progress_near`，rl-config `--table-near`，计划键 `table_near` |
| 只有策略自己产生的回合算梯度；读不出的回合按现有扣分 | 方向 1 里所有回合都是策略产生的；读不出照旧在 S0 回报里扣 0.1；这一回合位姿没动，逐回合项约 −0.03 × φ |
| 默认关的开关：连续两回合真实距离不变再扣 0.05 | `stall_penalty`（默认 0）：这一回合和上一回合 d 都没变（三个 d 都已知）就从这一回合的值里减去；第一轮不开 |

## 5. 方向 2（引导式采样）的方案要点

- **向导：** 按距离表贪心。
  - 从当前位姿试每个原子动作，用环境自己的动作和碰撞规则，查表取 d 最小的；平手按固定的动作顺序。
  - 这是确定的，所以同一道题的 8 条轨迹前缀相同。
  - 只对最少步数 ≥ 6 的题和等距题加向导。
- **k 按阶段：**
  - 第 1–50 次 ⌈d\* ÷ 2⌉；
  - 第 51–100 次 ⌈d\* ÷ 4⌉；
  - 第 101–150 次 0。
  - 需要把更新次数传进智能体循环（verl 的 trajectory_info 里已有 step，要多传一层）。
- **向导回合怎么写进序列：**
  - 写成和策略回答同样的格式（`<think>…</think><action>a|b|</action>`），每回合的动作数和 think 文本照 C0 SFT 数据；
  - token 的掩码置 0，只当历史，不进梯度；
  - 渲染照常。
  - 格式的细节在方向 2 的设计稿里给出选项，请你定。
- **向导期间的碰撞和读不出：**
  - 向导只走表里合法的转移，按构造不会碰撞，也不会读不出；
  - 如果运行时和表不一致（位姿不在表里、或撞了），向导就在那里停下交给策略，并计数。
- **回报和组内比较：**
  - 向导回合的奖励不计入回报，组内比较从接手的状态开始；
  - 方向 1 的逐回合项只算策略回合。
- **评测和验证一律不加向导。**
- **报告内容：**
  - 向导回合占比；
  - 难题（d\* ≥ 6、等距题）上出现成功的题数随更新的变化。
- **一个约束：** 本线的评测和训练任务从这个 worktree 的工作目录直接读代码。rw_tc1 训练和评测期间，这个 worktree 里的代码不能改。所以方向 2 要么等 rw_tc1 评完再合进来，要么开第二个 worktree（决定 1 的甲）。
