# 逐步功劳分配：方案和估算（2026-11-01；不占 GPU、不写训练代码）

> 用户 11-01 的第 1 项。目标：不再把一局的奖励加总后整局排名，改为每个回合单独算功劳：
>
> c_t = r_t + 3.333 ×（0.99 × φ_{t+1} − φ_t）
>
> - r_t 是这一回合的 S0 奖励（成功 +5、读不出 −0.1、碰撞扣分）；
> - φ 查现在的深度 12 表，成功时为 1；
> - 全成功、全失败的题不再丢。
>
> 本文只读代码、用已有训练记录在 CPU 上预算，没有改训练代码。

## 结论

1. **能做，改动不大。**
   - 每个回合在序列里的 token 范围，智能体循环已经在记（`turn_span`）；读不出的回合已经按这个范围传到了训练器（`invalid_turn_spans`）。
   - 每回合的奖励和 φ，环境本来就给。
   - 需要：新增 2 个文件；在 4 个现有文件里加默认关的开关。环境不用改。
2. **用已有记录预算**（rw_s0 的训练记录，61 次更新、69,758 个回合，CPU 重放）：
   - 有成有败的题里，**32% 的回合**功劳的正负和现在整局优势的正负相反。比如失败局里走对的一步，现在被压低。
   - 现在被丢掉的全成功、全失败的题占 **76%**，其中 97.6%–100% 的回合有非零功劳。
   - 第 4 回合以后拿正功劳的比例：加同题同位置的基线时是 0.39，现在 S0 的整局优势只有 0.22。这正是 S0 走样的位置（见 `DRIFT_S0_20261101.md`）。
3. **两个设计点的答案**：
   - 最优动作一般不是 0 功劳：靠近目标的回合 97% 为正。"只剩压低"的风险在全失败的题里：那里负功劳占 62%。所以要用基线，并加正负质量的保护（第 3.1 节）。
   - 和整局组内比较：建议叠加，作为一个臂；纯逐回合作为另一个臂（第 3.2 节）。
4. **代价**：
   - 人力：写代码和测试约 2 天，CPU 预检 0.5 天，8 卡冒烟 0.5 天（约 6 卡时）；
   - 正式比较：两个新臂各 3 个种子，约 330 卡时，按池的排队情况 2–4 天。

## 1. 现在的优势值怎么算（读代码的结果）

| 环节 | 代码 | 现在的做法 |
| --- | --- | --- |
| 一局的奖励 | `vagen/agent_loop/gym_agent_loop.py` | 每回合 `env.step` 的奖励存进 `env_rewards`；局末 `reward_score = sum(env_rewards)`。verl 的 agent loop（`verl/experimental/agent_loop/agent_loop.py`）把它放在回答序列的最后一个 token（`rm_scores`）。训练器只看到整局总和。 |
| 优势 | `verl/trainer/ppo/core_algos.py` 的 `compute_grpo_outcome_advantage`，经 `vagen/ray_trainer.py` 的 `compute_advantage` 调用 | token 奖励按序列求和得一个标量，同题 8 局（`uid`）减均值除标准差（n − 1），再乘 `response_mask` 铺到整局所有回答 token |
| 组筛选 | `vagen/custom_filter/filter.py`（在算完优势之后执行） | `mixed_outcome` 只留有成有败的题；`keep_by_return_std` 再补回报差别大的全失败题 |
| 序列 | PPO 配置 `concat_multi_turn: true` | 一局是一条序列：回答 token 的 mask 为 1，观察 token（文字和图像）为 0 |
| 每回合的 token 范围 | `AgentData.add_generated_turn()` | 每生成一回合就记 `turn_span = [start, end)`，按回答序列的坐标。`end_turn()` 只保留读不出的回合 |
| 已有的按回合的开关 | `vagen/invalid_turns.py`（`algorithm.invalid_turn_nonpositive_adv`） | 读不出回合的范围经 `extra_fields["invalid_turn_spans"]` 传到训练器的 `non_tensor_batch`，在 `compute_advantage` 之后把这些 token 的正优势清零 |
| 已有的拆分优势 | `vagen/split_reward_adv.py`（V8，`algorithm.progress_adv_weight`） | 每局的进度回报经 `extra_fields["reward_parts"]` 传过去，成功和进度分开标准化 |
| φ | 环境 info 的 `current_potential_score`；`progress_version: optimal` 时就是表的 φ | S0 的环境配置加上 `progress_version: optimal` + `distance_tables_dir`，奖励仍是 S0 的（进度奖励开关关着），φ 照样算 |

**结论**：每个回合的 token 范围拿得到。只要把"只记读不出的回合"推广成"每个回合都记"，并带上这一回合的奖励、φ 的前后值和是否成功即可，路子和 `invalid_turn_spans` 一样。

## 2. 方案

**功劳和优势**：
- 功劳：c_t = r_t + k ×（γ φ_{t+1} − φ_t），k = 3.333，γ = 0.99。r_t 取 S0 的回合奖励；φ_{t+1} 在成功的回合取 1。
- 优势：A_t = (c_t − b_t) ÷ s。b_t 是基线（选项见第 3.1 节），s 是全批的标准差。
- 这一回合所有回答 token 都取 A_t；观察 token 仍是 0。

**筛选**：新筛选 `nominal`。按抽题顺序取前 12 道题，不看成败。每次更新仍是 12 组 96 局，规模不变；全成功、全失败的题不再丢。

**开关**（都默认关，不开时行为不变）：

| 位置 | 名字 | 取值 |
| --- | --- | --- |
| PPO 配置 | `algorithm.adv_estimator` | `turn_credit`（新） |
| PPO 配置 | `algorithm.turn_credit` | `{scale: 3.333, gamma: 0.99, baseline: none / turn_index / phi_bin, episode_weight: 0 或 1, min_positive_mass: 0.4, neg_clip: 3.0}` |
| PPO 配置 | `filter.name` | `nominal`（新） |
| 训练链计划 `rl` | `advantage`、`turn_credit`、`group_filter: nominal` | 照现有的 `progress_adv_weight`、`invalid_turn_nonpositive` 的写法，经 `training_prep.py` 写进 PPO 配置 |

**要改和新增的文件**：

| 文件 | 改动 |
| --- | --- |
| 新增 `vagen/turn_credit.py` | 纯函数：由每回合记录算功劳、基线、标准化、和整局优势叠加，以及正负质量的保护 |
| 改 `vagen/agent_loop/gym_agent_loop.py` | 开关开时，每回合记 `{span, reward, phi_before, phi_after, success, valid}`，写进 `extra_fields["turn_records"]`（照 `invalid_turn_spans`）。约 30 行 |
| 改 `vagen/ray_trainer.py` | `compute_advantage` 里加 `turn_credit` 分支，把每回合的 A_t 写到对应的 token 范围。约 20 行 |
| 改 `vagen/custom_filter/filter.py` | 注册 `nominal` 筛选。约 25 行 |
| 改 `data_gen/interiorgs_v10/training_prep.py`、`train_chain.py` | 计划键到 PPO 配置。约 30 行 |
| 新增测试（`reward/tests/test_turn_credit.py` 等） | 合成批数据：每个 token 的优势、span 和 `response_mask` 对齐、筛选的结果 |

- 环境不用改：φ 已在 info 里，S0 + optimal 的环境配置现成。
- 这些改动在主线的文件里，按本线"只新增文件和开关、不改主线正在用的代码"的规矩，只加默认关的分支，只在 `reward-design` 分支上改。开工要你批（第 6 节）。

## 3. 两个设计点

### 3.1 最优动作功劳为 0 时，会不会只剩"压低坏动作"的更新？怎么防

**数据**（rw_s0 的记录重放；rw_o 的记录结果相同）：

| 回合类型（按表的 d） | 占回合 | 功劳 > 0 | 功劳 = 0 | 功劳 < 0 | 功劳中位数 |
| --- | --- | --- | --- | --- | --- |
| 离目标更近 | 34.2% | 97.3% | 0.7% | 2.1% | +0.33 |
| 不变 | 26.8% | 0 | 1.4% | 98.6% | −0.04 |
| 更远 | 28.4% | 0 | 3.2% | 96.8% | −0.35 |
| 成功 | 8.4% | 100% | 0 | 0 | +5.6 |
| 读不出 | 2.1% | 0 | 0 | 100% | −0.12 |

- 靠近目标的回合几乎都是正功劳。为 0 的 0.7% 都在离目标太远、φ 被截到 0 的地方，那里靠近一步也不加分。
- "不变"的回合是小负数：γ = 0.99 让原地不动也略亏。
- **风险在全失败的题里**：
  - 没有成功奖励，正功劳只来自靠近一步（约 +0.33）；负功劳来自原地、离远、碰撞、读不出。
  - 负功劳占 62%，只有 28% 的回合是正的。
  - 如果把这些题原样加进训练，它们的更新以压低为主。概率会流向别的输出，包括读不出的回答，和 S0 走样的机制一样。

**防法（推荐组合）**：
1. **基线用同题同位置的均值**（`baseline: turn_index`）：同一道题 8 局的第 t 回合求平均，作为这一回合的基线。
   - 预算：
     - 第 1 回合 8 局起点相同，61% 的回合减完后是 0；
     - 第 4 回合以后拿正功劳的比例从 0.29（不减基线）升到 0.39；
     - 全批的正负质量平衡。
   - 比整局优势（第 4 回合以后 0.22）给后几回合留了更多正向的锚。
2. **正负质量的保护**（`min_positive_mass`）：每次更新里，正优势 token 的总质量不低于负的 40%；不够时缩小负的一侧。
3. **负优势截断**（`neg_clip: 3.0`）：单个 token 的负优势不超过 3 个标准差，防止个别 token 被压得太狠。
4. **保留现有的保护**：KL 0.05 拉回 SFT 起点；读不出 10% 的停止线；加一条预警，读不出的 10 次均值过 1% 就报。
5. **φ 截到 0 的区域不另做处理**：那里功劳为 0，不产生更新，由成功奖励兜底。

### 3.2 要不要和现在的整局组内比较叠加

- **叠加**：A_t = z(整局的 S0 回报) + w × z(c_t − b_t)，w = 1（`episode_weight: 1`）。
  - 好处：保留"这局成没成功"的信号；逐回合功劳只调整局内哪一步该奖。
  - 代价：两个量的尺度要对齐。两项各自标准化后相加。
- **纯逐回合**（`episode_weight: 0`）：
  - 成功的信号只在成功那一回合（+5）出现，之前走对的几步只拿 +0.33。
  - 对靠多步才成功的题，前面的步子信用变弱。
  - 用 γ 折扣的"到局末的回报"可以补，但又回到整局求和的思路。
- **推荐两个都跑**：
  - 臂 TC-mix：叠加，w = 1；
  - 臂 TC-pure：纯逐回合；
  - 对照用 B 已有的 O（rw_o，种子 1）和 S0（两个种子），再补对照的第 3 个种子。
- **备注**：带势函数的逐回合回报，求和后等于"S0 的回报减去起点的 φ"，即 φ 当了状态价值的基线（Ng 1999 的势函数整形）。所以 TC-mix 的整局部分用 S0 回报就够了，不必再加进度奖励。
