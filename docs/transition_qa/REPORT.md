### 结论

1. **按预登记：D 学会了回答转移题，但没有用到动作上。** 这是预登记第 4 节写好的读法（"H2 成立而 H1 不成立"）。
   - **H1 不成立。** H1 是"D 的动作成功率高于 C"。D − C 四个 RL 合起来 +4.5 个百分点，95% 区间 +1.8 到 +7.4，符号检验 p 0.002。两个种子 +5.3 / +3.8，同号。但差不到 5 个百分点的门槛。
   - **H2 只在 goal 两类成立。** H2 是"D 在探针题上高于 C、C0"。
     - D − C：`goal_now`（目标现在是否达成）+15.5，`goal_after`（走一步后是否达成）+17.1，都是 p < 0.001，两个种子同号。
     - 遮挡平衡准确率 −1.5，不成立。
   - **H3 不成立。** H3 是"D 的'只差一个条件'的失败里，卡在'关系'条件上的更少"。实际 D 56.2%，C 53.1%。
2. **D 比 C 多出来的 4.5 个百分点，基本来自 D 多跑的更新。** 这一条是探索性的，预登记里没有。
   - C 的 4 个 RL 都在第 101 次更新以内被停止线停下。主指标用的是它们第 0–100 次的检查点，D 的 4 个都用第 300 次。
   - 把 D 取和 C 相同的更新次数：种子 1 的 S0 取第 50 次，V4 取第 0 次（即 SFT），种子 2 的 S0 取第 100 次，V4 取第 50 次。这样 D − C 四个合起来是 −0.5（95% 区间 −3.5 到 +2.2，p 0.77）。
   - 同样这 4 个 D 的 RL，第 300 次比上面这几个检查点高 5.1 个百分点（p < 0.001）。
   - 所以：在 C 跑得到的范围里，P1 没有让动作成功率更高。D 跑得更久时成功率还在涨，而 C 跑不到那么久。
3. **两组在稳不稳上差别很大。** 这是预登记第 5 节，另报，不做检验。
   - C 的 4 个 RL 全被停下：熵线 2 个（第 96、47 次），图像 token 崩溃 2 个（第 101、50 次）。
   - D 的 4 个都跑满 300 次。
   - E 停了 2 个，都是熵线（第 208、227 次）。C0 停了 1 个，是读不出线（第 150 次）。
   - 每组只有 4 个 RL，D 没有被停下是不是 P1 的作用，说不准。图像 token 崩溃是 Qwen3-VL 运行时的形状错误，和数据有什么关系也说不清。
   - 11-03 晚补做了三个 SFT 起点的采样验收（`PROGRESS.md` 12.45）。这是探索性的：预登记第 6 条写明它只作说明。
     - C 的起点熵 0.106，没过 0.06 的线；D 的 0.023、C0 的 0.024，都过。
     - C 被熵线停下的 2 个，可能和起点的熵高有关。但 E 从 C0 起步也有 2 个被熵线停下，只是晚得多（第 208、227 次），所以说不准。
4. **D 和 C0 比（次要比较）。**
   - 主指标 +3.3（p 0.018），不到 5，判"没有差异"。
   - 探针 goal 两类 +15.5 / +16.8，有差异；遮挡 −6.7，没有差异。
   - 按族、失败拆解都没有差异。
5. **E 和 C0 比（探索性）：哪一项都没有差异。**
   - 主指标 +2.2（p 0.106）。
   - 探针：`goal_now` −1.3，`goal_after` −0.3，遮挡 +0.8。
   - 失败拆解：差 0.0。
   - E 的 RL 几乎不写思考：带 `<think>` 的回答只占 0.01%–0.59%。所以"先想再答"在 RL 里没有留下来。

## 术语

- **状态 / 锚点状态**：状态是 SFT 轨迹上的一个相机位姿和它的图；锚点状态是拿来出题的状态。
- **门**：任务成功判据里的一项条件，例如"目标在画面里的部分不少于 95%"；全部通过才算成功。
- **状态题 / 前向题 / 逆向题**：
  - 状态题问当前这张图，例如"现在 A 在 B 的左边还是右边"；
  - 前向题问某个动作之后，例如"左转 40 度后哪个更近"，不另外渲染；
  - 逆向题给前后两张图，问相机做了什么动作。
- **P0 / P1 / P2**：三个 SFT 数据池。P0 是仿 8 个 benchmark 的 QA（第二版只用过 230 道样题；矩阵第三版用全量 10,144 条、11,458 道题），P1 是转移题，P2 是第十一轮的 SFT 动作轨迹。
- **正式题 / 后备题**：生成器给每个场景出的两批题。SFT 只用正式题，RL 只用后备题（第十一轮第 7 条决定）。
- **格式不合规**：探针题的回答不是题目要求的"只写选项字母 / 只写 Yes 或 No"；宽松读法仍可能读得出。
- **S0 / V4**：每个种子的一对 RL，两者只差奖励和补题方式。
  - S0 只在成功时给奖励。
  - V4 是主线登记的密集奖励：按离成功近了多少给奖励的势能整形，补题按回报的离散程度挑（`keep_by_return_std`）。
- **停止线**：RL 训练时的自动停止条件。
  - 熵线：最近 5 次更新的熵都高于 0.3，即回答变得太随机。
  - 图像 token 崩溃线：Qwen3-VL 的图像 token 数对不上、训练任务崩溃，连续 2 次就停。
  - 读不出线：最近 10 次更新里读不出的回答平均超过 10%（E 是 20%）。
- **探针**：838 道 P1 格式的问答题，出自验证场景，不拿来训练。用来看模型会不会判断当前状态和动作的后果。
- **符号检验**：只看"只有一边做对"的题，检验两边各占多少是不是对半开。
- **Holm 校正**：同时做多个检验时，把 p 值按个数调大，免得碰巧出一个小 p 值。

## 3. 风险和局限

- **矩阵第三版的结论能说到哪一步**：
  - D − C 里混着"跑了多少次"：C 的 RL 都在第 101 次以内停下，D 跑满 300 次。取同样的次数，D − C 是 −0.5（开头结论第 2 条）。C 跑不到后期，所以 P1 在 RL 后期有没有用，定不下来。
  - 几条链共用一个题集目录、同时评测时，主线的评测汇总（`evaluation table`）可能读到别的链正在写的结果。11-03 `m3_c_s20261021` 碰上过一次，重起那条链就过了。这一步不在补丁里，没改。
  - 每组只有两个种子。"同号"只说明两个种子方向一致，不说明稳定。
  - 测试集 292 道、四个 RL 合起来，能测出约 5 个百分点的差。主指标的区间上端是 7.4，所以真实的差有没有 5 个百分点，定不下来。
  - 探针和 P1 是同一种题。D 在探针上占优，说明它学会了这类题，不说明它在动作里用上了。
  - D − C0 里不止 P1 一项差别：C0 的 SFT 只练 P2q（没有 P0），挑 epoch 的题集不同，没去掉边缘场景，KL 线 0.2，也没有 11-02 加的两条停止线。
  - E − C0 除了提示，还差在 KL 线、两条停止线、RL 题去掉了边缘场景、读不出线 20%（预登记定稿后说明第 4 条）。
  - "稳不稳"每组只有 4 个 RL，没做检验。
- **评测集换了**（2026-10-29）：矩阵用去掉边缘场景的 v2 评测集（验证 382、测试 292，其中 59 道是补的），成功率和第十二轮的数不完全可比；C0 在新测试集上已补齐（合起来 292 道：P1-S0 43.2%、P1-D 42.8%（其中补进来的 59 道 40.7%、45.8%，原题 233 道 43.8%、42.1%；完整的 eval_test_v2 上是 40.1%、40.8%））。场景类型是按物体标签推的，清单里仍可能漏掉边缘场景。
- **P0**：11-02 起用全量 10,144 条（11,458 道题，698 个 train 场景），验证从 val 场景按题组抽 300 条；之前的 164 条样题版没有训练过。
- **goal 题占比高**：`goal_now` 占状态题 68.5%、`goal_after` 占前向题 47.7%，两类合计占训练集 51.5%（44,000 / 85,413）。探针显示现有模型在这类题上只会答 No；D 组练了以后能否改过来，看 D 的探针结果。
- **遮挡题少、答案不均，遮挡物按实心包围盒算**：
  - 遮挡族只占正式题的 2.8%；训练集的遮挡题（582 道）和遮挡任务的 goal 题（1,442 道）都已暂扣，测试集没有遮挡题（全部进了探针集）。

- **左右前向题的答案几乎从不改变**：转身不改变两个物体的左右顺序。这是物理事实，照实保留。
- **逆向题的动作分布**：动作来自最短路径；按选项格配平后，训练集以转身、侧移 2 次为多。逆向题只有 9.6%（配平去掉的多），没碰到 15% 的上限。
