# Q38 C 线预登记 v1（Qwen3.8-27B 上重训 Cambrian-S 第四阶段，含预测头）

- 写于 2026-11-24，两臂正式训练提交之前；此时 C 线没有任何评测数字（训练还没开始）。
- 本文件提交（下面"提交记录"里的 commit）之前，不读、不报任何 C 线评测数字；评测照常跑。
- 以后只能追加 v1.x 小节，写明日期、改了什么、为什么、改在看到哪些数字之前还是之后；v1 正文不改。
- 名词：
  - **复制基线**：用"当前时间单元的特征"去猜"下一个时间单元的特征"，不经过预测头。
  - **时间单元**：27B 把相邻 2 帧合成 1 个单元，2 fps 下 1 单元 = 1 秒。
  - **nfp_cos**：预测特征与真实下一单元特征的余弦距离（1 − cos），对所有预测位置的 token 取平均，越低越好。
  - **nfp_mse**：同样的位置上，逐维均方误差的 token 平均。

## 1. 训练（两臂，各 8 机 64 卡，同时跑）

| 项 | 设置 |
|---|---|
| 基座 | `q38/models/Qwen3.8-27B`，不做 1–3 阶段 |
| 数据 | `q38/s4/built/s4_v2`。VSI-590K 的问答共 590,667 条：视频 374,148 条 + 图像 216,519 条。另加 nfp 样本 290,000 条（从视频问答里按固定种子无放回抽，只算预测损失），合计 880,667 条；分词结果在 `q38/s4/tok/s4_v2` |
| 留出 | 60 段视频（不重复视频的 1%，种子 0）的 nfp 窗口不进训练，每段取 4 个窗口，共 240 条（`nfp_heldout.jsonl`）。这些视频的**问答行仍在训练里**（`heldout_scope nfp`），见差异表 X3 |
| 轮数与步数 | 1 个 epoch，3,441 步。全局批 256 = 64 卡 × 每卡 1 条 × 梯度累积 4 |
| 优化 | 学习率 1e-5，热身 3%（HF 向上取整，104 步），余弦衰减，weight decay 0，梯度裁剪 1.0，bf16，梯度检查点，种子 42 |
| 视频 | 问答样本：不论视频长短，都在整段视频上均匀取 256 帧（linspace 取整；短视频会重复帧，和官方"一律取 128 帧"同一做法；`lf_video.py`）。nfp 样本：2 fps 下的一段连续窗口，最多 128 个单元（256 帧），短于窗口的视频取全部帧。每帧像素上限 65,536（约 256×256，每单元约 64 个 token）；序列上限 16,384；模板 qwen3_8，`enable_thinking false` |
| 图像 | 每张像素上限 65,536（`image_max_pixels`，阶段 2 用户决定 5），每张约 64 个 token |
| 冻结 | 视觉编码器冻结；训练 merger（连接器）+ 语言模型 + 语言头（+ C-NFP 的预测头） |
| 损失 | 文本项：每条问答样本先在自己的有标签 token 上取平均，再把一个优化步里所有问答样本的值相加、除以 256（nfp 样本的文本项是 0）。预测项：一个优化步里全部预测位置的 token 平均。总损失 = 文本项 + 0.1 × MSE 项 + 0.1 × 余弦项。两臂相同（C-noNFP 的预测项权重为 0）。和官方的区别见差异表 R12 |
| C-NFP | MSE 0.1 + 余弦 0.1；预测头 = 两层 MLP + GELU（5120 → 1152），输入 = 语言模型隐层，目标 = 编码器 blocks[25] 输出按 2×2 合并窗口取平均 |
| C-noNFP | 两个权重都是 0：模型不挂预测头。nfp 样本留在数据里，但不产生任何损失，所以两臂的步数、学习率曲线和数据顺序完全相同（阶段 2 用户决定 1："照跑"） |
| 存盘 | 每 500 步存一次：完整存盘（续训用，含优化器状态）只留最新 1 个；每次存盘后做一份 bf16 副本（不带续训文件），全部保留。第 3,441 步再存一次完整存盘和 bf16 副本。每臂共 7 份 bf16 副本：500、1000、…、3000、3441 |
| 代码 | 训练代码是提交时 HEAD 的 git archive 快照（`RUN/code`），写进 `plan.json` |
| 停训守卫 | `vagen.q38s4.tools.guard`（269a857d），每 2 分钟查一次。任一条触发就停训并报告：损失非有限数；C-NFP 最近 200 个带 nfp 的步 nfp_cos 都不低于复制基线；最近 20 步中位步时 > 2 × 25.76 秒（第 21 步起）；无新步超时（平时 30 分钟，存盘步后 60 分钟，最后一步后 120 分钟，开训前 75 分钟，续训开训前 120 分钟）；任一机器已用内存 > 1,600 GB；存盘或 bf16 副本失败 |

**守卫停训后怎么算**：
- **预测头规则停了 C-NFP**（200 步不低于复制基线）：判定 1 直接记为"头没学到"（依据是训练日志），不重启；C-NFP 的判定 2、3 记为"未判"；C-NFP 已有的 bf16 副本只作探索性评测；C-noNFP 照常跑完。
- **NaN 停了**：报告用户，由用户定是否从上一个完整存盘续训。
- **机器或存储的原因停了**（吞吐、无新步、内存、存盘失败、任务失败）：从最新完整存盘续训。每臂最多续训 2 次；还跑不完，这一臂记为"未完成"，用到它的判定记为"未判"。
- 续训仍算同一次训练（续训恢复数据顺序和优化器状态），报告里写明停在哪一步、续训了几次。
- 某一臂跑不完时，判定 2、3 等它跑完，不拿中间点代替。

## 3. 判定 1：预测头学到了

- **数据**：上面的 240 条留出 nfp 样本。
- **权重**：C-NFP 最终 bf16 副本，带预测头。
- **怎么算**：
  - 视频的处理和训练时完全一样（2 fps、最多 128 个单元、每帧像素上限 65,536）；
  - 单卡，HF transformers，bf16，推理模式；
  - 预测位置和目标与训练时相同：第 t 个单元的隐层预测第 t+1 个单元的目标特征；
  - 对 240 条样本的全部预测位置，按 token 取平均，得到 nfp_cos，和训练日志的口径相同；
  - 复制基线在同样的位置上算：copy_cos = 1 − cos(第 t 单元目标, 第 t+1 单元目标)。
- **判定**：相对降幅 r = (copy_cos − nfp_cos) / copy_cos。
  - r ≥ 0.20 → **头学到了**；
  - r < 0.20 → **头没学到**：A、B 不启动，先查实现。
- **只记录、不作判定的**：
  - nfp_mse 与 copy_mse；
  - 按样本平均的 r；
  - 按视频重抽 2,000 次的 95% 区间；
  - 对照：一个随机初始化的新头（与训练相同的初始化，种子 0）在同样数据上的 r，用来确认"头学到"不是计算方式带来的。
- **工具**：新写 `vagen/q38s4/tools/nfp_heldout.py`，带单测，用 1 卡 sco 任务跑。
  - 复用 `vagen/q38s4/nfp.py` 的目标和损失函数；只读权重和留出集，写一个结果目录。
  - 预测头的 4 个张量（`nfp_head.fc{1,2}.{weight,bias}`）从 safetensors 里显式读出、装进头里，再和文件里的值逐位比较，不一致就报错退出。这样不会因为加载器忽略了这些键而拿随机头去算。单测覆盖这一条。

## 4. 判定 2：预测损失不伤问答

- **评测**：EASI-8，用 `data_gen.interiorgs_v10.qa_eval` 的 `easi_8`。
  - 包含 vsi_bench、mmsi_bench、mindcube_tiny、viewspatial、site、blink、3dsrbench、embspatial；
  - site 拆成 site_image、site_video 两个任务（各自一个文件夹），所以一共 9 个任务；
  - 设置与基座 `q38-base-zs-easi` 的计划相同（`easi "easi_8"`，`cards {"site_video": 2}`），评测时的输入和生成设置见差异表 X7。
- **每个 benchmark 的分数**（EASI `backends/lmmseval.py` 的主指标，0–100，EASI 已取 4 位小数）：

  | benchmark | 主指标 |
  |---|---|
  | vsi_bench | `vsibench_overall`（各子任务不加权平均） |
  | mmsi_bench | `average`（全部样本的平均） |
  | mindcube_tiny | `overall_accuracy` |
  | viewspatial | `overall_accuracy` |
  | site | 两部分合起来的 CAA（chance-adjusted accuracy，扣掉随机猜对的部分）：按 EASI `_extract_site_scores` 的定义，把 site_image 和 site_video 两个文件夹里的逐样本 caa_num、caa_den 分别求和再相除；两部分各自的 CAA 也单列 |
  | blink | `blink_acc`（14 个子任务不加权平均） |
  | 3dsrbench | `vanilla_accuracy`（不用 `circular_accuracy`，它只作子分数） |
  | embspatial | `embspatial_acc` |

  - 主线代码里没有把 site 两个文件夹合起来的程序，所以新写一个小脚本，直接调用 EASI 的 `_extract_site_scores`（把两个文件夹最新的 jsonl 放进同一个目录），带单测；基座的 site 也用同一个脚本算。
- **EASI-8 均值**：8 个 benchmark 分数的不加权平均；用 EASI 给的 4 位小数分数直接算，不再取整（报告里显示 1 位小数）。
- **判定**：d = C-NFP 最终 − C-noNFP 最终（EASI-8 均值，单位：百分点）。
  - d > −2 → **不伤**；
  - d ≤ −2 → **伤**；
  - d ≥ +2 时另记"C-NFP 高"，不作判定。
  - 参照：官方 VSI-Bench 掉 1.4，所以 vsi_bench 单项的差也单列。
- **两臂设置相同**：包括第 8 节可能加的生成上限和栈转储开关。
- **任务崩了怎么办**：一个任务没有写出 `done.json`（进程报错退出，或分数缺失），用同一设置重跑，最多重跑 2 次。
  - site 的一部分若进程返回非 0 但分数已写出，`qa_eval` 照样接受（现有代码如此），不重跑。
  - 重跑 2 次还不行，这个 benchmark 两臂都不用：只用两臂都有的 benchmark，写明是 EASI-k（k 为个数），不是 EASI-8。k < 6 时判定 2 记为"未判"。

## 5. 判定 3：第四阶段对本线有没有价值（C-NFP 最终 vs 27B 基座）

- **3a 动作题**。
  - 题目：705 道标准集里的验证集 413 道（`eval_val_v2`）。
  - 采样：T 0.8，top-p 0.92，采样种子 20261016，跑 1 遍。
  - 其他设置：最多 12 轮，每轮 384 token，带历史，`--format-example action_names`，`--entropy`，vLLM 显存占比 0.9。设置与基座的 `q38base_t08` 完全相同。
  - 指标：成功率。
  - 判定：Δ = C-NFP − 基座。Δ ≥ 5 个百分点 → **有帮助**（种子噪声 3–5 点）。
- **3b 探针**。
  - 题目：`p1_probe.jsonl` 的 838 道（`VAGEN-Lite-data/exps/transition_qa_20261019b/p1_probe.jsonl`），指标是准确率 = 答对数 / 838。
  - 解码（`vagen/q38/qa_probe.py`，与基座相同）：贪心（temperature 0），其余用 vLLM 默认（`generation_config "vllm"`，不读模型自带的生成配置），无系统提示，`enable_thinking false`，max_model_len 4,096。
  - 被截断的回答照样解析，不跳过；解析不出答案的算错，仍在分母里。
  - 两个口径：
    - 256：探针默认（`--max-tokens` 不设），结果在 `out/probe`；
    - 1,024：计划里设 `probe_variants {"probe1024": {"max_tokens": 1024}}`，与基座 `q38-base-zs-probe1024` 相同，结果在 `out/probe1024`。
  - 基座在 256 口径下有不少回答被截断，所以要求两个口径都满足。
  - 判定：两个口径都是 Δ ≥ 10 个百分点 → **判断能力涨了**。
- **3a、3b 都不过** → 第四阶段不直接帮动作，C 的产物只作 A、B 的起点。
- **只记录、不作判定的**：
  - 每题配对的 McNemar p 值；
  - C-noNFP 对基座的同样两个差；
  - C-NFP 对 C-noNFP 的同样两个差。

## 8. 评测的执行方式

- **跑法**：
  - 评测用主线的 `eval_only` 训练链计划，从 s4 工作树运行，NORMAL 优先级，只用空闲机器；
  - 每次评测的评测集复制件起新名字，不重用。
- **C-NFP 先摘掉预测头**：vLLM 0.28 的 qwen3_5 加载器不认 `nfp_head.*`，遇到就报错。
  - 新写 `vagen/q38s4/tools/strip_head.py`，带单测。
  - 它生成一个评测目录：没有头的分片用软链；含头的分片重写一份，只去掉 `nfp_head.fc{1,2}.{weight,bias}` 4 个张量（冒烟存盘里它们都在最后一个分片）；新的索引；config 和分词器文件复制过去。
  - 校验：键集合 = 原键集合 − nfp_head 的 4 个；其余张量逐字节相同。
  - C-noNFP 没有头，直接评 bf16 副本。
  - 判定 1 用带头的原副本。
- **生成长度**（任务说明阶段 5 第 6 条）：
  - 第一份 bf16 副本（C-NFP 第 500 步）出来后，每个问答 benchmark 先抽 50 题，测平均回答 token 数和每题秒数，估算整个 benchmark 的时长。
  - 预计 > 3 小时的 benchmark，设一个生成上限，作为 v1.x 追加并登记为差异。追加在看到任何正确率之前写，两臂用同一个上限。
  - 动作题（每轮 384）和探针（256 / 1,024）的上限已经固定，不受这条影响。
- **EASI 的已知问题**：s4 分支的 `qa_eval.py` 给每个 qwen3_5 的 EASI 任务装一个每 15 分钟转储一次调用栈的线程（c2c6ed47）。主线 C0 e5 的 mmsi_bench、3dsrbench 4 次里 4 次在转储时 SIGSEGV。开关在 qwen38-mx 分支的 a2e069ca（计划里设 `qa_eval "no_stack_dump": [...]`，默认关），s4 分支没有。
  - 做法（第 11 节第 3 条，用户已批准）：把 a2e069ca 拣进 qwen38-s4，C 线所有 EASI 任务（两臂、中间点）都设 `no_stack_dump`。
  - 这个开关只决定装不装转储线程，不改模型输入、解码和打分，所以和基座（装了转储线程）的分数可以比。
  - 设了开关还崩，按第 4 节重跑最多 2 次。

### 重复窗口

- 240 条留出样本里只有 128 个不同的窗口：不同窗口共 678,908 个预测位置，240 条合计 1,058,256 个。原因：
  - 46 段视频短于 128 个单元，窗口取全部帧、长度凑成偶数（第 1 节"视频"一行）。
    - 2 fps 下帧数为偶数的 19 段：窗口就是整段，4 条完全相同。
    - 帧数为奇数的 27 段：窗口比整段少一帧，起点只能是第 0 帧或第 1 帧，u = 0.125 和 0.375 两条相同、0.625 和 0.875 两条相同，只有 2 个不同窗口。
  - 1 段视频（scannetppv2/52599ae063，2 fps 下 258 帧，只比一个窗口多 2 帧）有 3 个不同窗口。
  - 其余 13 段各有 4 个不同窗口。
  - 合计 19 + 27 × 2 + 3 + 13 × 4 = 128。
- 判定 1 口径的 r 把这些窗口算了 2–4 次（规则不变，照算）。按视频重抽时，同一视频的 4 条一起抽，重复不会让区间变窄。报告里不把 240 条当作 240 个独立样本。
