# "磁盘紧张就不提交"约定（方案，等你批）

2026-10-26 写。要各线改代码，批了再由你转达。

## 结论

- 用一个固定路径的标志文件：`/mnt/umm/users/yinbaiqiao/disk_runs/flags/STOP_SUBMIT_DISK_LOW`。
- 磁盘线的监控在剩余低于 1.5 TB 时写入它，剩余回到 3 TB 以上时删掉。
- 各线提交新的训练任务前先看它在不在：在就不提交，过几分钟再看。已经在跑的任务不受影响，监控也不会去停任何任务。
- 这样可以避免 10-20 那种整夜写满、所有训练链在存检查点时一起挂掉的情况。

## 规则

| 项 | 内容 |
| --- | --- |
| 路径 | `/mnt/umm/users/yinbaiqiao/disk_runs/flags/STOP_SUBMIT_DISK_LOW` |
| 谁写、谁删 | 只有磁盘线的监控（`disk/monitor.py`），别的线只读 |
| 何时写 | 剩余（22 TB − 配额表已用）低于 1.5 TB。配额表只给整数 TB，实际就是配额表读数到 21 TB 时写 |
| 何时删 | 剩余回到 3 TB 以上（配额表读数到 19 TB 及以下）。中间留空档，避免在一个整数附近反复开关 |
| 内容 | 一行 JSON：写入时间、配额表读数、剩余、门槛，让读的人知道为什么停 |
| 警告文件（已在用） | `disk_runs/WARN_DISK_LOW`：剩余低于 3 TB 时写，只提醒、不拦 |
