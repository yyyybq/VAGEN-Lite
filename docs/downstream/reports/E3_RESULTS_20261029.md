# E3 RL：结果（2026-10-29）

> 依据：第四步的方案（[STEP4_RL_PLAN_20261023.md](STEP4_RL_PLAN_20261023.md)），以及你 10-26 晚、10-27 的决定：从各起点 E2 30% 的第 20 万步出发；3 个任务；训练中自评关掉，加看门狗。四个起点都训完了 100 次更新，导出后用同一套 944 回合评过。

## 结论

1. **RL 没有让任何一个起点变好，S 和 RD 反而显著变差。** 944 回合上，RL 前 → RL 后：
   - B：34.2% → 33.3%（−0.9 个百分点，逐回合 McNemar p = 0.46）；
   - RS：36.4% → 36.9%（+0.4，p = 0.81）；
   - S：33.7% → 30.2%（−3.5，p = 0.004）；
   - RD：34.7% → 31.6%（−3.1，p = 0.013）。
2. **变差主要发生在 RL 没训的 31 个任务上**：S −2.9（p = 0.02），RD −3.3（p = 0.012）。也就是说，RL 损害了别的任务。在 RL 训的 3 个任务上，RS +6.0（p = 0.20），B −2.7，S −6.7（p = 0.11），RD −2.0，都不显著。
3. **起点之间比"RL 带来的变化"，没有显著差别。** 每个起点的变化减去 B 的变化，按任务平均：S −3.2（p = 0.075），RS +1.4（p = 0.41），RD −2.6（p = 0.25）。
4. **RL 训练时几乎没有拿到成功的信号。**
   - 训练时采样回合的成功率（RLinf 的 `success_once`）从第 1 次到第 100 次更新都只有 0%–2%。
   - 同样这 3 个任务，在评测里是 32%–43%。
   - 评测里成功的回合，86%–100% 在 512 步以内结束（RL 一个回合的长度就是 512 步），所以不是回合太短。
   - 原因未核实，可能有两个：RLinf 的 `success_once` 统计口径和我们不同（例如按步而不是按回合）；或者 RLinf 环境里的观测、场景和我们的评测不一样。
   - 如果是后者，RL 等于在几乎没有正信号的情况下更新，这正好对得上 S、RD 在没训的任务上变差。
5. **建议**：以后不论在哪个骨干上再做 RL，都先在 RLinf 的环境里用不更新的策略跑一遍，看成功率和我们的评测对不对得上（约 1–2 卡时）。Qwen2.5 的远迁移已经收口，这个核对要不要现在做，等你定。

## 做法

- **起点**：各起点 E2 30% 的第 20 万步（`DS-<起点>-030-s1/run/final_model`，只按路径读）。
- **任务**：按"四个起点平均成功率在 10%–60% 的空间任务"这条规则，用 30% 的检查点重算，选出 3 个：CoffeeSetupMug、StackBowlsCabinet、TurnOffStove（你 10-27 确认）。
- **RL 设置**：RLinf 的 PPO，100 次更新，32 个环境，每个回合 512 步；轮转和训练轮数各 2，演员学习率 5e-6，梯度裁剪 1.0，每 20 次更新存一个检查点。
- **自评和看门狗**：训练中的自评关掉，因为 10-27 第一次开跑时 B、RS 都在它之后卡死了；另加看门狗，40 分钟没有新的更新就结束任务。
- **评测**：训完导出成 StarVLA 格式，用 944 回合评测，和 RL 前用的是同一套。
- **缺的一个回合**：RD 的两次评测都少一个回合，都是 OpenDrawer 种子 1012，仿真进程连死 3 次后被放弃。X3 重放时、模型线的 DS-Q3S 评测里也是这个回合。
- **卡时**（按任务时长估，未核实）：
  - 每个起点约 21 小时训练，加约 3.5 小时评测，8 卡，约 200 卡时；四个约 800 卡时。
  - 另外花在失败尝试上的：10-27 卡死的第一次约 62 卡时，10-26 从 E1 出发的旧 E3 约 37 卡时。
- **文件**：结果在 `downstream_runs/report_e3_20261029/`（`results.json`、`results.md`），代码 `downstream/x/e3_analyze.py`（测试 `test_e3_analyze.py`）。
