# X4 能力保留结果（2026-10-27）

> 依据：你 10-26 晚的决定 6（"允许导出 4 份 HF 副本（约 66 GB）；8 个模型都评 v2 验证集和评测集；B 和 E1-B 的提示格式先从主线评测记录确认再提交"）。设计见 [X_DESIGNS_20261026.md](X_DESIGNS_20261026.md) 的 X4 一节。

## 结论

1. **四个起点经过 E1 的动作微调后，主线能力全部丢失。** 四个 E1 模型在 v2 验证集（413 道）和评测集（292 道）上都是 0%。原始起点是：B 5.8% / 9.2%，S 40.9% / 37.7%，RS 47.7% / 42.1%，RD 45.5% / 43.5%（验证集 / 评测集）。每个 E1 模型和自己的原始起点逐题比（McNemar），都是 p < 10⁻⁶。
2. **原因是文字生成整个退化了，不是答错。** 四个 E1 模型每一步的回答都无效（评测集 876 / 876 步，验证集 1,239 / 1,239 步），每道题都因"连续无效回答"结束。回答的内容：E1-B 全是一长串空格；E1-S、E1-RS 绝大多数是一长串"1"；E1-RD 是空格、"<"加换行、"1"等重复字符。原始起点几乎没有无效回答（评测集：B 0 / 3,085 步，S 1 / 2,077，RS 0 / 1,921，RD 60 / 2,096），回答都是 `<action>move_forward|</action>` 这样的格式。
3. **导出没有问题。** 导出的 HF 模型和 StarVLA 检查点：张量名完全一致（729 个），抽查的 15 个张量逐位相同；vLLM 加载时没有报缺权重，占用显存和原始 B 一样（15.63 GiB）。
4. **为什么会这样（机制已核实，因果是推断）。** E1 只用动作损失训练，动作头读的是语言模型的隐状态。语言模型 28 层和最后的归一化层都被改了（例如最后归一化层的权重和原始 B 最多差 0.031），但输出文字用的 `lm_head` 不在动作损失里，没收到梯度，和原始 B 逐位相同。送进 `lm_head` 的隐状态变了，`lm_head` 却没跟着变，输出就退化成重复字符。

所以，用 E1 这种全量微调，四个起点之间"保留了多少"分不出来：都是零。要比保留程度，可以看只训动作头的 X1（语言模型冻结，原有能力按构造不变）和 LoRA 的 T2；另一个办法是不看成功率，而是看 E1 模型在主线答案上的词元损失（困惑度），这样能分出损伤程度。这个没做，要不要做请你定。

## 做法

- **导出**：主线的 `scripts/export_starvla_backbone.py`，把 E1 最终检查点（`DS-<起点>-100-s1/run/final_model/pytorch_model.pt`，只按路径读）里的视觉语言模型去掉前缀后存成 HF 格式，配置文件从起点复制，动作头不导。1 个 1 卡任务（`pt-tevrpc90`），每份约 69 秒、16 GB，共 4 份，在 `downstream_runs/x/X4/hf/`。
- **评测**：主线的评测脚本（`sco_interiorgs_v10_train.sh eval`，vLLM 0.11，提示格式 `no_think`，贪心，最多 12 轮），16 个 1 卡任务，10-27 00:59–01:25 UTC（h800）。题目从主线的 `eval_{val,test}_v2/tasks.jsonl` 复制到我们的目录，结果只写在我们的目录。
- **提示格式**：主线评原始 7B 和评 RL 模型都用 `no_think`（主线评测记录里的 `model.json`），8 个模型都一样。
- **统计**：`downstream/x/x4_analyze.py`（测试 `downstream/tests/test_x4_analyze.py`）。
