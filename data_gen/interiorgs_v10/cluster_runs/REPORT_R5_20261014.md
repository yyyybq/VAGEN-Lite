## 先说清楚几个词

- **题（任务）**：一个场景，加上要找的目标物体、要达到的画面条件（成功判据），以及相机的起点位置和朝向。
- **正式题 / 后备题**：每个场景最多 14 道正式题；另外最多 16 道后备题，审核刷掉正式题时才补用。
- **族**：题的类型。projective_relations（左右）、absolute_positioning（到物体的距离）、screen_occupancy（物体在画面里的高度）、equidistance（等距）、occlusion_alignment（让目标被挡住，简称 OA）、fov_inclusion（两个物体同框，简称 FOV）。
- **最少步数 d\***：从起点出发，最少几个动作就能满足成功判据。动作是前进、后退、左移、右移各 0.3 m，左转、右转各 20°。
- **面清楚可见（可见规则）**：把物体的 3D 标注框看成盒子，盒子的某一个面朝向相机、面上 25 个采样点里足够多的点在画面内且没被挡住、露出部分在画面上足够大。成功画面里每个必须认出的目标都要有一个这样的面。
- **面露出比例**：这个面的 25 个采样点里，在画面内且没被挡住的点所占的比例。
- **画面面积**：露出部分在 256×256 画面上所占的比例。
- **嵌入式物体**：冰箱、洗衣机、洗碗机这类嵌在柜子或墙里的电器，标注框常和柜子、墙重叠。
- **重叠余量**：遮挡物离目标的框不到 0.10 m 时不算遮挡，避免把嵌在柜子里的冰箱算成被柜子挡住。
- **参照物**："沙发旁边的边几"里的沙发，即描述目标时借用的另一个物体。
- **R1 旧规则开关** `r1_legacy_success`：打开时环境判断成功不看可见规则和 45° 规则，和 R1 当初一样。
- **回放**：把题目给的最短走法在环境里一步步执行，看是否恰好在第 d\* 步第一次成功、中途有没有碰撞。不渲染。

## 二、三个问题的修改

三处改动都在 `vagen/envs/active_spatial/target_visibility.py`（规则版本 `face_visible_v2`）和 `data_gen/interiorgs_v10/referring.py`；环境判断成功、生成器出题和求最少步数都调用同一组函数。打开 `r1_legacy_success` 时环境不用这些规则。

### 1. 左右 45°

- **规则：** 成功画面的相机视角下，在地面上取从 B 中心指向 A 中心的线，它和相机左右方向的夹角不超过 45° 才算左右。超过 45° 环境不判成功，生成器也不会把这样的位姿当终点。
- **前后题：** 代码里的 projective 题只有左和右两种，本轮没有新增前后题。
- **第四轮样本的违规数：** 355 道左右正式题里 115 道（32%）终点超过 45°；395 道后备题里 142 道（36%）。新样本 380 道正式题、419 道后备题里都是 0 道。

### 2. 只在需要时加描述

按这个顺序选第一种能用的：

1. **只写名字**：整个场景里这类物体只有一个（按读者会怎么理解来算，"the table" 也会指边几、餐桌）。
2. **用房间**：InteriorGS 的房间没有名字，所以从房间里的家具推断房间类型。有马桶、浴缸、洗手盆是卫生间；有灶台、油烟机是厨房；有床是卧室；没有这些时，有沙发是客厅，有餐桌是餐厅，有书桌是书房；同时有两种强信号（比如床和马桶）或者厨房里有沙发（开放式），就不定类型。只有目标所在房间的类型已知，而且场景里其他同类物体所在房间的类型都已知且都不同，才用"the X in the R"。
3. **用参照物**：见下一条。
4. **用大小**：场景里正好两个同类物体，在同一个房间，体积（或高度）差 1.5 倍以上："the larger X"。
5. 都不行：这个物体不出题。

参照物不能是目标的一部分，也不能和目标重叠、压在目标上或被目标压着：两者的 3D 框相交，或者地面投影的重叠超过较小那个的 10%，就不能当参照物。例如床垫、床上的枕头不能当床的参照物。

### 3. 参照物要选好

- **够大：** 参照物的标注框里最大的面（两个最大边长相乘）至少 0.25 平方米，约 50 cm × 50 cm。
  - 理由：训练画面 256×256，水平视角 90°。0.5 m × 0.5 m 的面在 3 m 外约占 21×28 像素，画面的 0.9%，是可见门槛 0.3% 的 3 倍；完全露出时在约 5 m 内都能过可见门槛，而出题的物体对相距最远 5 m。
  - 按尺寸排除，不写类别名单。钟、纸巾盒、插线板、托盘这类小东西都在 0.25 平方米以下。
- **在它所在的房间里唯一：** 同一房间里没有第二个同类物体。另外整个描述放到全场景里也必须只指向一个物体：比如两个卧室各有一个衣柜、旁边各有一张床，"the bed next to the wardrobe"就不能用。
- **成功画面里和目标一起可见：** 题目里记下每个目标的参照物（`ref_anchor`），环境判断成功时要求它和目标一样满足可见规则。OA 题被挡的那个目标不要求可见，它的参照物也不要求。

## 六、训练准备

### 1. SFT 数据

- **用哪些题：** train 的正式题做训练数据（10,477 道），val 的正式题做验证数据（1,351 道），test 不用。每道题按题目给的最短路径生成一段多轮对话，只有轨迹，不混 QA。
- **对话格式：** 和 RL 环境一样的系统提示；每个用户回合有一张图和"Current camera pose"一行；助手只回答动作，每回合是一串相同的连续动作（最多 5 个）。
- **全量需要渲染的画面：** 39,746 帧，来自 847 个场景，帧列表已经写好（`interiorgs_v10_gen_20261014/sft/`），还没有渲染。
- **工具：** `training_prep.py sft-frames / sft-records`，然后 `scripts/prepare_active_spatial_sft.py` 生成 LLaMA-Factory 的数据和配置。

### 2. 抽查（用 100 个样本场景的试跑数据）

- **"当前相机位姿"一行和 RL 提示一致：** RL 试跑时环境实际给模型的输入，和同一道题的 SFT 对话对比：64 个首回合，系统提示 64 个完全相同，首个用户回合（含位姿一行）64 个完全相同。
- **occlusion_alignment 的提示里没有目标的方向和距离：** 108 个 OA 用户回合，去掉位姿一行和题目原文后，0 个含方向词、距离词或数字。环境里的两个 OA 提示开关第四轮起默认关闭。
- 每帧都有图，1,165 道题全部生成了对话，没有一道被丢弃。

### 3. 配置（沿用以前的设置，必须改的地方单列）

**SFT：** 沿用 `prepare_active_spatial_sft.py` 的配方：Qwen2.5-VL-7B（R1 用的同一个预训练权重），全参数微调，冻结视觉部分，学习率 1e-5，3 个 epoch，每卡 batch 1、梯度累积 8，最长 16,384 个 token，bf16，8 张 H800。必须改的地方：

| 改动 | 原因 |
| --- | --- |
| 不混 QA（`--qa-probability 0`） | 你的要求 |
| 允许没有审核的轨迹（`--allow-unreviewed-trajectories`，写进输出清单） | 本轮不做模型审核；原配方只收审核通过的轨迹 |
| 用 accelerate + FSDP 分卡（`accelerate_fsdp_qwen25vl.yaml`） | 环境里没有 DeepSpeed；以前的 Qwen2.5-VL SFT 也是这样跑的 |
| 关掉 LLaMA-Factory 的版本检查 | 它要求 transformers ≤ 4.52.4，环境里是 4.56.1（RL 需要）；试跑证明能正常训练 |
| SFT 系统提示里的奖励数字改成 RL 的（格式奖励 0、格式错误 -0.1） | 系统提示里写了这两个数，原来 SFT 和 RL 不一样 |

**RL：** 沿用 dense-score 试验的 S0 分支（稀疏奖励，上次三个分支里终点最稳定的）：PPO（no_concat_gae，γ = λ = 0.95），actor 学习率 5e-7，critic 2e-5，每步 12 道题、每题 4 条轨迹，KL 损失 0.3，700 步的学习率计划；训练 8 张 H800 加渲染 1 张，zoetrope 池。环境配置见 `configs/rl_env_v10_S0.yaml`。必须改的地方：

| 改动 | 原因 |
| --- | --- |
| 提示格式 no_think（只答动作） | SFT 数据只有动作，RL 要从 SFT 模型接着训，两边提示必须一样 |
| `r1_legacy_success: false` | 按 v10 的新规则判断成功 |
| 从 v10 SFT 模型开始，不是从预训练权重开始 | 你的计划：先 SFT 再 RL |
| 验证用 64 道均匀抽取的 val 题（以前是 R1 的 32 道） | val 有 1,351 道，全用每次验证要几个小时 |
| 不做 R1 那种"渲染画面比对"的数据证书 | 它要逐题渲染并和审核过的图片比对；本轮用 CPU 回放和试跑代替 |
