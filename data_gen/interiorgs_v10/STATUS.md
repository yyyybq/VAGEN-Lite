## 2. 已定的决定

"题"（任务）指：一个场景、要找的目标物体、要达到的画面条件（成功判据），以及相机的起点位置和朝向。
"最少步数"指从起点到满足成功判据，最少需要几个动作（前进、后退、左移、右移、左转、右转，每步 0.3 m 或 20°）。

| 日期 | 决定 |
| --- | --- |
| 2026-10-10 | 起点画面里至少一个目标能被认出来；终点画面里所有目标都能被认出来；起点必须合法且尚未成功。（例外见 2026-10-12 第 2 条） |
| 2026-10-10 | 同类物体可以出现多个，用空间描述（附近的参照物、大小等）区分；描述不唯一的物体不出题。 |
| 2026-10-10 | 题型扩展到 projective 以外，新题型用 v2 判据（`canonical_spatial_task_h1_v2`）；projective / FOV 的 v1 判据保持逐位不变。 |
| 2026-10-12 | **俯仰保持水平。** `horizon_locked` 运动模型留在代码里，只用于实验，不用于任何正式数据（环境只实现了水平的 r1 运动）。 |
| 2026-10-12 | **occlusion_alignment（让目标被遮住）的终点只要求遮挡物能被认出来。** 同时目标的投影必须在画面内、并落在遮挡物后面被它挡住（判据要求目标 8 个角都在相机前方、至少 80% 的轮廓在画面内、其中至少 85% 被挡住），不能只是出了画面。这是"终点所有目标都能认出"的唯一例外。GPU 审核时这个族改问"目标是否被遮挡物挡住"，审核图上画出目标的投影框。 |
| 2026-10-12 | **按族配额，软上限。** 每个场景：projective 2–6、absolute_positioning 2–4、screen_occupancy 2–4、equidistance 1–3、occlusion_alignment 1–2（"2–6"指至少 2 道、最多 6 道）。别的族都出不了题时，允许某个族超过上限，把 14 道补满。 |
| 2026-10-12 | **后备题。** 每个场景 14 道正式题之外，最多再准备 16 道后备题。GPU 审核按需使用：只有正式题被刷掉的场景才渲染和审核后备题。 |
| 2026-10-12 | **split。** R1 的 45 个训练场景固定进 train，7 个评测场景固定进 test，其余按场景数 80/10/10 划分；同一物理场景的多个导出（同源组）必须进同一份。同源组文件必须显式传入，不传就报错。 |
| 2026-10-12 | **时间预算按工作量计。** 同样的输入每次得到完全相同的结果；预算为 600 个工作量单位（理由见 `cluster_runs/REPORT_FULLRUN_20261012.md`）。 |
| 2026-10-12 | **标注错误的物体被忽略**（碰撞、遮挡、出题三处都不再使用），清单为 `configs/ignored_objects_20261012.json`；无法确定的不自动忽略。 |
| 2026-10-12 | **最少步数 d\* 必须和环境一致。** projective 题生成器的成功规则比环境多一道遮挡门槛（两个目标都至少一半没被挡住）。所以只保留"按环境自己的规则，恰好在 d\* 步第一次成功"的起点（配置项 `runtime_success_check`）。环境和 v1 判据都不改。（由本轮第 6 项"回放时成功要恰好在 d\* 出现"推出，具体做法由我选定；要不要改成在环境里也加遮挡门槛，见第 4 节第 2 项。） |
| 2026-10-12 | **FOV（两物体同框）族暂不加入。** 它的画面质量门槛只用 15 道人工通过的题标定过，没有人工判为不合格的反例；R1 的标定报告结论是"在有人工反例标定之前不能用于训练"。 |

## 3. 训练前必须做的事（按顺序）

1. 打补丁（都只改 `vagen/envs/active_spatial/` 的副本或正式代码，按这个顺序）：
   1. `families/canonical_task_metrics_v2.patch`：让环境认识 v2 判据（新题型）。
   2. `patches/env_structure_override.patch`：让需要"坐标方向覆盖"的场景用生成器校准的方向（这些场景的房间轮廓 Y 方向用旧规则判不出来）。
   3. `patches/env_ignored_objects.patch`：让环境忽略每道题 `collision_convention.ignored_object_ids` 里列出的错误标注框。
   在副本上验证这三个补丁的工具是 `replay_env.py`（见第 5 节）。
2. 训练配置里关掉 occlusion_alignment 的提示：`enable_occlusion_task_guidance: false`、`enable_occlusion_occluder_hint: false`。
   否则环境会把目标相对相机的方向和距离（按实时位姿算的）写进提示，这是模型本不该知道的信息（见 `families/ENV_INTEGRATION.md`）。
3. SFT 导出不显示"当前相机位姿"一行，而 RL 提示里有；混合 SFT 和 RL 之前要让两边一致。
4. 只用 GPU 审核通过的题（审核用哪个模型见第 4 节第 1 项）。

## 4. 待决事项

按影响大小排序。每项写了可选做法和代价；推荐项放在第一个。

1. **GPU 审核用哪个模型。**
   - 详见 `cluster_runs/GPU_PLAN_20261012.md`。集群上完整可用的是 Qwen3-VL-8B、InternVL3.5-8B 和 Qwen2.5-VL-7B；更大的模型权重不完整。
   - 可选做法：
     - (a) **推荐：** Qwen3-VL-8B 和 InternVL3.5-8B 两个模型各审一遍，合并结果。审核约 2–8 GPU·小时。
     - (b) 只用 Qwen3-VL-8B。GPU 时间减半，但模型的错误没有第二票来纠正。
     - (c) 从集群外拷一个 30B 以上的模型进来。审核质量的上限更高，代价是传输和约 3–4 倍的 GPU 时间。
   - 无论选哪个，都要先做 200 道题的人工对照试点，人工约 2–3 小时。需要确认由谁来标。
2. **projective 的遮挡门槛只放在生成器，还是也放进环境。**
   - 现在环境只用 v1 判据。训练时如果模型走到"一个目标被挡住大半、但 v1 判据满足"的位置，环境也算成功。
   - 生成器已经保证题目给的最短路径的终点两个目标都看得见，并且 d\* 和环境一致；但模型自己走时，可能在目标被挡住的地方就拿到了成功。
   - 可选做法：
     - (a) **推荐：** 先保持。环境不改，R1 的成功定义也不变。
     - (b) 用补丁把同样的遮挡门槛加进环境。这样环境和生成器完全一致，`runtime_success_check` 也就不需要了。代价是改了 R1 的成功定义（推翻 2026-10-10 的决定），环境每一步还要多做一次遮挡计算；需要再写一个补丁并在副本上验证，约半天，之后要按新规则重新出题。
3. **726 个"无法确定"的标注框怎么处理。**
   - 现在它们没有被忽略，仍然挡路、挡视线、能被选为出题目标。
   - 可选做法：
     - (a) **推荐：** 人工过一遍。每个框一张俯视图，已经画好，在本机 `exps/interiorgs_v10_cabinet_audit_20261012/figures_uncertain/`。约 3–4 小时，确认是错的就加进忽略清单，然后只重跑受影响的场景。
     - (b) 保持现状，代价是部分房间出题少。
     - (c) 定一条更宽的自动规则，例如"框里能看穿的面积 ≥ 30% 且盖住房间一半以上"。代价是可能把真实的环形或 L 形家具也去掉。
4. **忽略合并柜子以后，沿墙那圈真实柜子没有碰撞体。**
   - 生成器要求相机离墙至少 0.5 m，所以生成的题基本不受影响。但训练时模型自己走，可能贴墙走进柜子里；被忽略的框里有 107 个高于 1.8 m。
   - 可选做法：
     - (a) **推荐：** 先接受。在 RL 试跑里统计相机进入被忽略框沿墙 0.6 m 带的次数，再决定要不要处理。
     - (b) 把被忽略的框改成只去掉离墙 0.6 m 以外的部分，沿墙一圈仍算碰撞。生成器和环境补丁都要改，约半天，并且要重跑受影响的约 270 个场景。
5. **FOV（两物体同框）族要不要加。**
   - 可选做法：
     - (a) **推荐：** 先不加。
     - (b) 加。要先做约 300 道题的人工盲标（正例和反例各至少 100 道），人工约 1–2 小时，GPU 几分钟；然后重新标定画面门槛，再把 FOV 加进配额重跑。
6. **GPU 阶段后备题用完仍不足 14 道的场景怎么办。**
   - 可选做法：
     - (a) **推荐：** 保持不足。
     - (b) 回 CPU 阶段，为这些场景加大搜索范围重新出题，例如放宽每个族的物体数上限。代价是少量 CPU 时间，以及这些场景的结果和本轮不再完全一致。
7. **少数大场景在"找终点"阶段花费被低估。**
   - 例如 0141：时间预算按工作量计以后，它的"找终点"阶段比以前跑得久，留给"找起点"的预算变少，最后只有 11 道题（以前 14 道）。
   - 可选做法：
     - (a) **推荐：** 接受。只影响极少数场景，且结果可复现。
     - (b) 给"找终点"阶段加一个按物体计的上限，例如单个物体最多花 30 单位。代价是要改代码，并让这些大场景的结果和本轮不同。
