## 2. Gap fills for (a): a websocket policy server for the official evaluator that calls π0.5 internally and swaps its prompt per subtask

### 2.1 Evaluator-facing contract (consolidated, all [code])

- **Transport.** One port serves both HTTP `GET /healthz` → 200 and the websocket.
  - Reference server: `B1K/OmniGibson/omnigibson/eval/utils/network_utils.py:182-276`, using `websockets.asyncio.server.serve(..., compression=None, max_size=None, process_request=_health_check)` (`:204-212`).
- **When the client connects.** The client connects lazily. `WebsocketClientPolicy.__init__` only stores the URI (`network_utils.py:62-70`). The connection, health check and metadata read happen in the first `reset()` (`:172-177`), which is called after scene/instance load (`evaluator.py:563`, `:627`).
  - So the policy server may start after the evaluator, up to the moment loading finishes.
  - HEAD: the health check retries forever (`:83-92`).
  - 2026-eval: the init allowance is 600 s (`2026-eval:.../evaluator.py:58,767-781`).
- **On connect, send one msgpack dict first.**
  - 2026-eval reads it with `recv(timeout=10)` (`2026-eval:.../network_utils.py:142`).
  - HEAD reads it with no timeout (`network_utils.py:106`).
- **Inbound messages**
  - (i) `{"reset": True}` once per `run()`. On a single port this is one reset for all N envs. Never reply to it (`network_utils.py:172-179`; reference server `:226-228`).
  - (ii) An observation dict. Keys for the default robot:
    - `robot_r1::robot_r1:{zed_link|left_realsense_link|right_realsense_link}:Camera:0::rgb`: uint8, shape (N,H,W,4).
    - `…::depth_linear`: float32, shape (N,H,W). Present only with RGBD.
    - `robot_r1::proprio`: shape (N,61).
    - `robot_r1::cam_rel_poses`: shape (N,21).
    - `task_id`: int64, shape (N,1).
    - `__action_chunk_size__`: an int, only if chunk replay is enabled.
    - Sources: key construction `eval_utils.py:233-245` + `robots/robot.py:1431,1515-1526` + `evaluator.py:576-592`; shapes `sensors/vision_sensor.py:966-968`.
- **Reply.** Exactly one binary msgpack dict with `"action"` as an ndarray of shape (N,23), or (23,) when N=1. Text frames make the client raise (`network_utils.py:134-135`).
- **Batching.** N is `--num-envs` on a single port. It is 1 per port with `--policy-endpoints` (`2026-eval:.../policies.py:200,209-212`).
- **Unknown keys.** Ignore them, and do not assume only three cameras exist [inferred]. Sensors not named in `eval.camera_sensor_names` keep the 1080² default (`evaluator.py:273-279`, `r1pro.yaml:30-34`). The R1Pro USD is not in the repo, so whether extra cameras exist is NOT FOUND.

### 2.2 Calling π0.5 with a per-subtask prompt (verified building blocks)


**Option B (separate process).**

**Facts that matter for prompt swapping:**
- **No JIT recompilation on a prompt change.** Tokens are padded to the fixed `max_token_len` (200 for π0.5) (`tokenizer.py:34-48`; R4 for 200).
- **Long prompts get cut.** The prompt is `"Task: {prompt}, State: {23 discretized ints};\nAction: "`, and truncation drops the tail. A long prompt therefore loses the state tokens and the `Action:` suffix (`tokenizer.py:22-47`). Keep subtask prompts short [inferred].
- **The tokenizer model downloads at startup.** It comes from `gs://big_vision/paligemma_tokenizer.model` into `$OPENPI_DATA_HOME` (default `~/.cache/openpi`) (`tokenizer.py:18`; `shared/download.py:22-33`). Pre-cache it in an offline Docker image [inferred].
- **Chunk validity.** Each chunk is absolute targets computed from the state at inference time (`MappedAbsoluteActions`, R4 §2.2). Executing up to 16 of the 32 steps is the baseline's practice (`serve_b1k.py:35-37`). Returning them as an `action_chunk` of exactly K ≤ 16 is valid for both evaluator versions (C11). On a subtask or prompt change, flush the buffer and re-infer, as `B1KPolicyWrapper.reset()` clears buffers (`eval_b1k_wrapper.py:42-49`) [inferred design].
- **Language may not steer the stock checkpoint.** See §0.3. Treat the official checkpoint as effectively unconditioned on language. Per-subtask steering needs a checkpoint fine-tuned on subtask strings, for example from the per-episode annotations (`docs/challenge/updates.md:51`).
- **Prompt source for full-task prompts.** `S/research/r9_tasks_jsonl_groot_my.jsonl` (`task_name` or NL `task`). For the stock checkpoint, a `task_name`-style prompt such as `"turning_on_radio"` is the more likely training distribution (§0.3) [inferred].

### 2.3 Robustness requirements not stated together elsewhere

- **Keep slow work off the event loop.**
  - On 2026-eval each reconnect attempt is one 2 s health check plus a 10 s open and a 10 s metadata wait (`2026-eval:.../network_utils.py:115-142,151-171`).
  - At HEAD, the client has `ping_timeout=300` (`network_utils.py:98-105`).
  - So run LLM and π0.5 calls in a worker thread. The OPENPI B1K server blocks the loop (`websocket_b1k_server.py:73`).
- **Make the first query do the warm-up.** On 2026-eval the first query of each rollout is uncharged but capped at 600 s (`2026-eval:.../evaluator.py:783-791`). Do JAX compile and initial planning there.
- **Budget for turning_on_radio.** 3224 s of accounted time for ≤ 3225 queries.
  - Single-port: wall clock, including sim stepping and video writing.
  - Multi-port: own query time plus sim share.
  - Sources: `2026-eval:.../evaluator.py:157,884`; `2026-eval:.../policies.py:162-177,218-228`.
- **Reconnects resend the same observation.** 2026-eval resends the same obs after a reconnect (`2026-eval:.../network_utils.py:208-210`). Keep episode state outside the connection handler and make processing idempotent for a repeated obs [inferred].
- **GPU co-location.**
  - The documented π0.5 server sets `XLA_PYTHON_CLIENT_MEM_FRACTION=0.85` on `CUDA_VISIBLE_DEVICES=0` (`docs/challenge/baselines.md:171-182`).
  - A BEHAVIOR simulator needs about 10.5 GB [3p-docs `RAX/docs/BEHAVIOR_BACKEND.md:87,269`].
  - On one 24 GB GPU these cannot coexist [inferred]. Put the sim on another GPU (`OMNIGIBSON_GPU_ID`, `B1K/OmniGibson/omnigibson/macros.py:138`) or lower the JAX fraction.
